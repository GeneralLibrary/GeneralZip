## 读数要点

1. **吞吐排序符合算法预期**：LZ4/ZSTD（快）> Deflate/GZ（中）> LZMA2/XZ/BZ2（慢但压缩比高）。
2. **加密开销**：
   - WinZip AES-256 相对明文 Deflate 约有 15–25% 压缩端损耗（.NET AES-CTR + HMAC-SHA1）；
   - **SM4-GM 高可压数据下仍达 ~104 MB/s**，不可压数据约 15–25 MB/s——纯 C# SM4 的常数时间实现是主要成本；对吞吐敏感场景建议外层先压后用 SM4（ZIP 内部即此顺序）；
   - ZipCrypto 因逐字节异或流，解压损耗明显，仅作兼容演示。
3. **7Z 压缩较慢**（~3–10 MB/s）：LZMA2 高压缩比档 + 写入经暂存目录两段落盘（v1 实现）；解压吞吐正常。
4. **GZ 解压极快**（文本 6.1 GB/s）：.NET 内置 GZipStream 高度优化，推荐作为纯托管场景的默认选择。
5. ZIP-Store 吞吐受 CRC32 逐字节计算与文件 IO 支配；随机数据下 SM4-GM 解压 28.8 MB/s 为自研 SM4 的当前水位，后续可引入查表/T 表优化。

## 复现

```powershell
dotnet run -c Release --project samples/GeneralZip.Bench -- [大小MB] [预热次数] [测量次数]
# 默认: 8 MB × 3 类负载，预热 1 次，测量 3 次
```
